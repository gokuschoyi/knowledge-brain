# Demo Walkthrough

This guide walks through a complete Knowledge Brain demo in about 10 minutes. It covers the full `Ingest → Retrieve → Evaluate → Repair` cycle and highlights what makes this system different from plain RAG.

---

## Before You Start

1. The app is running at `http://localhost:5173`
2. At least one LLM API key is configured (`GOOGLE_API_KEY` minimum, plus one generation provider)
3. A brain is created (or use the default one)

---

## Step 1 — Open Dashboard

**What to show:** The metrics panel. Document count, entity count, claim count, relationship count, and average quality score.

**Talking point:** "Everything you see here is live telemetry over the knowledge base. The quality score isn't a sentiment score — it's computed from entity coverage, claim grounding, and chunk-level extraction completeness. A score of 0 means we just ingested raw text with no structure. A score approaching 1 means the knowledge is dense, cross-referenced, and well-defined."

---

## Step 2 — Ingest a Document

Navigate to **Ingest**. Upload one of the sample documents (or paste text directly).

Suggested sample: paste or upload a document about a product, company, or research paper with specific named concepts and numeric claims (pricing, dates, statistics work well for showing contradictions later).

**What to show:** The upload form. Choose the LLM provider and model.

**Talking point:** "The extraction model is selectable per ingest — so you can use a cheaper model for bulk ingestion and a more capable one for complex documents. The embedding model is fixed to Gemini to keep the vector space consistent."

---

## Step 3 — Watch Ingestion Progress

Stay on the Ingest page and watch the progress panel update in real time.

**What to show:** The stage-by-stage progress (text extraction → chunking → chunk extraction → finalization), followed by per-chunk artifact status.

**Talking point:** "Each chunk is processed by the LLM in parallel — you can see the chunk tasks completing independently. This is not sequential RAG chunking. Each chunk gets bundled entity, claim, and relationship extraction in one prompt, and the results are consolidated at the end to avoid writing duplicate entities from different chunks."

---

## Step 4 — Open Knowledge Graph

Navigate to **Knowledge Graph**.

**What to show:** The entity-relationship graph rendered by ELK. Zoom in on a cluster of nodes. Click one node to open the details panel.

**Talking point:** "The graph is not a keyword graph. These are canonical entities extracted from the text, with confidence scores, descriptions, and relationship edges grounded in specific evidence chunks. The layout is computed client-side by ELK — the backend just returns nodes and edges."

Point out any isolated entities in the separate tab: "Isolated entities have been extracted but have no relationships yet. They're candidates for enrichment — the self-healing system can write better definitions for them automatically."

---

## Step 5 — Ask a Question in Chat

Navigate to **Research Chat**. Ask a question that is clearly answerable from the ingested document.

Suggested question: `What is [main concept from your document] and how does it relate to [another entity you saw in the graph]?`

**What to show:** The streaming answer appearing token by token. The source panel with grounded evidence chunks. The confidence score badge.

**Talking point:** "The answer is not generated from the raw text. The retrieval pipeline does vector search, then expands graph context — pulling in entity definitions, claims, and relationship edges connected to what the question is asking about. The answer is grounded in the top evidence chunks, and you can see exactly which ones."

---

## Step 6 — Ask a Question with Gaps

Ask a question about something the ingested document does not cover well.

Suggested: ask about pricing, a specific date, or a detail that was only vaguely mentioned.

**What to show:** A lower confidence score (amber or red badge). The knowledge gaps panel listing what the system could not find.

**Talking point:** "When retrieval is weak, the system tells you. The gap list is generated by the retrieval agent assessing whether the evidence actually answers the question. This triggers a low-confidence repair task in the background — which means the next time someone asks this question, the system has already tried to find better evidence."

---

## Step 7 — Open Self-Healing Console

Navigate to **Diagnostic Console** (Self-Healing).

**What to show:** The pending task list. There should be tasks generated from ingestion: duplicate entity candidates, missing definition tasks, possibly contradiction tasks. There may also be a `low_confidence_answer` task from step 6.

**Talking point:** "These tasks were generated automatically — I didn't create them manually. Duplicate detection, missing definition flagging, and contradiction detection all run at the end of every ingestion. The low-confidence answer task was created when chat retrieved a weak answer."

---

## Step 8 — Run a Missing Definition Repair

Find a `missing_definition` task. Click **Run**.

**What to show:** The task status changes to `running`, then `completed`. Open the task detail panel and show the `result` field — it contains the newly generated entity definition.

Navigate back to **Knowledge Graph**, find the entity, and show its updated description.

**Talking point:** "The repair agent gathered evidence chunks for this entity, asked the LLM to write a grounded definition using only that evidence, and wrote it back. No human intervention needed. The confidence score on the entity also increased — but not to 1.0, because we cap confidence to avoid false certainty."

---

## Step 9 — Ingest a Contradictory Document

Go back to **Ingest**. Upload or paste a second document that makes conflicting claims about the same subject as the first document. Pricing that changes between documents works well.

**What to show:** After ingestion completes, navigate to **Diagnostic Console**. A new `contradiction` task should appear.

Open the task and show the detail panel — it lists the conflicting claims side by side.

**Talking point:** "Contradiction detection compares claims with the same subject across the knowledge base. Instead of overwriting one with the other, the system escalates to a review task. This is by design — contradictions require human judgement. The system flags it, surfaces the evidence, and waits."

---

## Step 10 — Show Auto-Repair Configuration

Navigate to **Knowledge Brains**. Open the active brain's settings.

**What to show:** Auto-repair toggle, interval setting, task type selection.

**Talking point:** "For low-risk repairs like missing definitions, auto-repair runs on a schedule without any human trigger. Higher-risk repairs like entity merges stay manual by default — merging entities changes the graph structure and is harder to undo."

---
